# tmn-korean-normalizer

한국어 AI 작문 패턴을 규칙으로 검출하고, 그중 판단이 필요 없는 9가지를 자동 교정한다.

[DaleSeo/korean-skills](https://github.com/DaleSeo/korean-skills)의 humanizer 스킬은 40개 패턴을
LLM이 매번 읽고 눈대중으로 판정한다. 그 판정 중 기계가 할 수 있는 부분을 정규식과 통계 지표로
옮긴 것이 이 도구다. LLM은 남은 의미 판단만 맡는다.

## 무엇이 규칙으로 옮겨졌나

| 계층 | 패턴 | 개수 | 처리 |
|---|---|---|---|
| A | 3, 6, 7, 15, 17, 19, 27, 31, 37, 108, 112, 113, 114 | 13 | 검출 + 자동 교정 |
| B | 나머지 전부 | 37 | 검출만, 교정은 사람이나 LLM |


1~40번은 원본 스킬을 그대로 옮긴 것이다. 다만 임계 스코프 하나를 팀 기준으로 바꿨다.
상류는 같은 표현이 한 문단에 몰릴 때만 신호로 보는데, 실제 글은 문단마다 하나씩 흩뿌리는
쪽이 흔해 임계에 닿지 않았다. 정의는 JSON 그대로 두고 로드 뒤 `widen_scope`에서 문단
스코프를 문서 스코프로 넓힌다. 횟수는 상류 값을 유지한다. 101번부터는 팀이 실사용에서 찾아 덧붙인 규칙이고
`rules/extra.json`에 따로 둔다. 원본 집합을 건드리지 않으려고 번호대를 나눴다.

| 번호 | 패턴 | 걸러내는 것 |
|---|---|---|
| 101 | '하나의' 부정관사 직역 | 영어 a/an을 옮긴 `하나의 완벽한 웹 페이지` |
| 102 | 지시대명사 복수형 | `이것들`, `그것들`, 무생물을 가리키는 `이들` |
| 103 | 피동 중복 | `반복되어 사용되는`처럼 피동이 겹친 형태 |
| 104 | 완전무결 과장 | `완벽한`, `최고의`, `유일무이` |
| 105 | 과장 어휘 밀도 | 어절 100개당 `독보적`, `폭증`, `극대화` 밀도. 38번을 대체 |
| 106 | 괄호 부연 | 코드와 링크를 뺀 산문의 모든 괄호 |
| 108 | 공허한 강조 관형어 | `핵심 수익 구조`, `주요 특징` |
| 109 | 부정 병렬 수사 | `단순한 X를 넘어`, `X에 그치지 않는다`, `A가 아니라 B다` |
| 111 | 번역체 상용 어휘 | `잡다`, `닫다`, 홀로 쓰인 `축` |
| 112 | 작품 제목 부호 오용 | 아스키 꺾쇠 `<로망스>` |
| 113 | 결말 표제 | `한 줄 요약`, `요약`, `정리`, `결론` 표제 줄 |
| 114 | 서두 예고 문장 | `정리해 드릴게요`, `살펴보겠습니다` |
| 115 | 짧은 문장 남발 | 25자 미만 산문 문장이 30% 초과 |
| 116 | 강조 부사 남발 | `완전히`, `매우`, `정말`, `아주` 밀도 |
| 117 | 마크다운 조각내기 | 목록·헤딩·굵은 글씨가 줄당 0.5 초과 |

111은 catch·close·pillar의 직역을 예외 없이 걸러낸다. `범인을 잡았다`, `문을 닫습니다`처럼
번역체가 아닌 쓰임도 함께 걸린다. 문맥으로 가르려면 대상 명사 목록이 필요한데, 목록이 늘어날수록
빠지는 자리가 생긴다. 걸러낸 뒤 사람이 판단하는 편이 낫다고 보고 예외를 두지 않았다.
`축약`, `구축`, `압축`, `건축`, `축소`, `축적` 같은 합성어는 대상이 아니다.

109는 아닌 것을 먼저 말하고 뒤집어 강조하는 구성을 찾아낸다. `철수가 아니라 영희가 왔다`
같은 정정도 포함한다. 처음부터 `영희가 왔다`라고 쓰면 되기 때문이다. 예외를 두지 않아
1회부터 신호로 본다.

106은 예외를 두지 않는다. [Enago의 괄호 지침](https://www.enago.co.kr/academy/mastering-the-art-of-parenthesis/)은
남발과 중첩을 피하라고만 하지만, 팀 답변 스타일은 그보다 엄격해 괄호 부연 자체를 금지한다.
판정 기준은 `tmn-cc-settings/hooks/style_check.py`의 `PAREN_ASIDE`와 같다. 코드 블록,
인라인 코드, 링크 타깃을 걷어낸 산문에서 반각·전각 괄호를 모두 센다.

원어나 축약어를 밝혀야 할 때는 괄호 대신 문장으로 푼다. `MFN(Most Favored Nation) SAFE`는
`MFN SAFE 방식으로 넣습니다. MFN은 Most Favored Nation의 줄임말입니다`가 된다.

Tier A는 예외가 없는 규칙이다. 이중 피동 `되어진다`는 한국어 어문 규범상 비문이고,
`~에 있어서`는 원본 문서가 자연스러운 사용처가 없다고 규정한다. 나머지는 빈도 임계를
넘겼다는 사실만 알려주고 어떻게 고칠지는 판단에 맡긴다.

**패턴 8~10 띄어쓰기는 자동 교정하지 않는다.** 원본 스킬이 제시하는 교정 예시
`할 수 있는것`, `공부하고있습니다`는 한글 맞춤법 제42항 의존명사 띄어쓰기와 제47항
보조용언 규정을 어긴다. KatFishNet이 관측한 것은 인간 텍스트의 띄어쓰기 분산이 크다는
통계지 붙여 쓰는 편이 옳다는 규범이 아니다. 검출만 하고 판단은 사람에게 넘긴다.

## 설치

레포를 클론한다. 팀 관례상 `~/teammono` 아래에 둔다.

```bash
git clone git@github.com:team-monolith-product/tmn-korean-normalizer.git ~/teammono/tmn-korean-normalizer
```

### 쓰기만 할 때

전역 명령으로 설치한다. 어느 디렉터리에서든 `korean-normalizer`를 쓸 수 있다.

```bash
uv tool install ~/teammono/tmn-korean-normalizer
```

갱신은 다음과 같이 한다.

```bash
cd ~/teammono/tmn-korean-normalizer && git pull && uv tool install --force .
```

### 고칠 때

레포 안에서 개발용 가상환경을 만든다. pytest와 ruff가 함께 설치된다.

```bash
cd ~/teammono/tmn-korean-normalizer
uv sync
uv run korean-normalizer detect examples/ai-sample.md
```

## 사용

아래는 전역 설치를 기준으로 한다. 개발 환경에서는 앞에 `uv run`을 붙인다.

```bash
korean-normalizer detect examples/ai-sample.md
```

```
자연도 등급: C — S1 4건, S2 4건으로 AI 흔적이 뚜렷함
감지 요약: S1 4건, S2 4건, S3 0건

[S1] 패턴 27 '~에 있어서' 격식 차용 — 문서 전체, 2회 (임계 1) [자동교정]
    지침: ~에서, ~의 경우로 환원하거나 통째로 지운다.
    · 되어집니다. 현대 사회에 있어서 데이터의 중요성은 매
    · 성은 매우 크다. 이 점에 있어서 모든 기업이 동의한다
```

JSON으로 받아 다른 도구에 넘길 수도 있다.

```bash
korean-normalizer detect 문서.md --format json
```

표준 입력도 받는다.

```bash
cat 문서.md | korean-normalizer detect
```

Tier A 자동 교정은 diff로 먼저 확인하고 반영한다.

```bash
korean-normalizer fix 문서.md --diff
korean-normalizer fix 문서.md --in-place
```

CI에서 문서를 검사하려면 종료 코드를 쓴다.

```bash
korean-normalizer detect 문서.md --fail-on-finding
```

규칙 목록과 tier는 다음으로 확인한다.

```bash
korean-normalizer rules
```

## 동작 원리

1. 산문이 아닌 부분을 자리표시자로 덮는다. 코드 블록, 인라인 코드, URL, 마크다운 링크
   타깃, 표 행이 대상이다. 표 칸은 명사구 나열이라 품사 비율을 왜곡하고, 칸 구분자를 넘어
   매치가 형성되면 표가 깨진다. 헤딩은 두 층으로 갈린다. 어휘 규칙은 헤딩까지 보고,
   통계 지표와 문장부호 규칙은 헤딩을 뺀다. 공허한 강조는 헤딩에 몰리지만 헤딩은 문장이
   아니고 부호 관습도 본문과 다르기 때문이다. 오프셋은 그대로 두어 원문에서 스니펫을 다시
   잘라낸다. 큰따옴표 직접 인용은 검출은 하되 교정에서 제외한다.
2. 문단과 문장으로 나눈다.
3. `rules/*.json`의 규칙을 적용한다. 정규식 규칙은 문서 단위로 빈도 임계를 확인하고,
   통계 규칙은 지표를 계산해 경계와 비교한다. 표본이 모자라면 판정을 건너뛰고 그 사실을 남긴다.
4. S1/S2 건수로 자연도 등급 A~D를 매긴다.
5. `fix`는 임계를 실제로 넘긴 자리에서만 치환한다. 1회 등장이 자연스러운 표현을 건드리지 않기
   위해서다. 치환이 다른 규칙의 대상을 만들 수 있어 결과가 안정될 때까지 최대 3회 순회한다.

`-들`을 지우면 앞말의 받침이 사라져 조사가 어긋난다. `사용자들이`에서 `들`만 빼면
`사용자이`가 되므로, 치환 뒤 받침을 보고 조사를 다시 고른다.

## 지표 규칙을 넣기 전에

새 지표 규칙의 경계는 반드시 사람이 쓴 한국어 산문과 대조해 정한다. 원본 스킬에서 가져온
규칙 2·11·12·13은 그 검증 없이 경계를 옮겨 적었다가 사람 글에서도 전부 발화해 뺐다.

```bash
python3 tools/collect_corpus.py                       # 위키백과 2019년 판본 26편
python3 tools/calibrate.py noun_ratio human_corpus.json
```

2019년 이전 판본만 받는다. 그 뒤 편집은 AI 도움을 받았을 수 있다.

| 지표 | 당시 경계 | 사람 위키백과 26편 | AI 답변 30건 |
|---|---|---|---|
| 쉼표 상대 위치 | > 0.15 | 중앙 0.466, 발화 100% | 중앙 0.471, 발화 100% |
| 명사 비율 | > 0.35 | 중앙 0.766, 발화 100% | 중앙 0.788, 발화 100% |
| 동사·형용사 비율 | < 0.25 | 중앙 0.156, 발화 100% | 중앙 0.147, 발화 100% |
| 품사 3연쇄 다양성 | < 0.5 | 700토큰 창 0.514 | 700토큰 창 0.544 |

앞의 셋은 경계가 한국어 산문이 도달할 수 없는 값이라 모든 입력에서 발화했다. 논문이 말한
비율과 이 구현의 분모가 달랐다. 3연쇄는 길이가 길수록 값이 떨어져 문서 길이를 맞춰 다시
쟀더니 AI가 오히려 높았다. 규칙이 가정한 방향과 반대다.

## 규칙 추가

`src/korean_normalizer/rules/*.json`에 항목을 더한다. 코드 수정은 필요 없다.

```json
{
  "id": 41,
  "name": "패턴 이름",
  "severity": "S2",
  "kind": "regex",
  "pattern": "정규식",
  "exclude": "예외 정규식",
  "threshold": { "scope": "paragraph", "count": 3 },
  "autofix": [{ "pattern": "찾을 것", "replacement": "바꿀 것" }],
  "guidance": "교정 지침 한 줄"
}
```

통계 규칙은 `"kind": "metric"`으로 두고 `metrics.py`에 등록한 지표 이름과 경계를 적는다.
`autofix`를 넣는 순간 그 규칙은 Tier A가 되므로, 반례가 없는지 먼저 확인한다.
